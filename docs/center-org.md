# 가상 센터 편제 (에이전트 운영)

센터장은 본인이다. 에이전트는 실행을 맡고, 센터장은 판단, 승인, 방향을 맡는다.
상세 프롬프트 템플릿과 승인 정책은 [agent-roles.md](agent-roles.md)를 따른다.

## 1. 1차 가동 편제 (8개 역할 + 총괄)

| 역할 | 파일 | 모델 | 권한 | 용도 |
|---|---|---|---|---|
| 총괄 비서 | (메인 세션) | 기본 | 전체 | 분류, 위임, 종합, 승인 요청 전달, bot 전송 |
| 품질·검증 | `.claude/agents/verifier.md` | opus | 읽기 전용 | 코드·설정·연구 독립 검증 |
| 일일 점검 | `.claude/agents/daily-check.md` | haiku | 읽기 전용 | 서버 상태·로그·인증서 점검 |
| 응대 | `.claude/agents/responder.md` | sonnet | 읽기 전용 | bot 문의 분류와 응답문 작성 |
| 문서 | `.claude/agents/doc-writer.md` | sonnet | docs 쓰기 | 런북, 보고서, 주간 리포트 |
| 리서치 수집 | `.claude/agents/researcher.md` | sonnet | 읽기 + 웹 | 주제별 병렬 수집 |
| 팩트체커 | `.claude/agents/fact-checker.md` | opus | 읽기 + 웹 | 핵심 주장 재확인 |
| 서버 설정 | `.claude/agents/infra-config.md` | opus | 읽기 + 변경안 문서 | 변경안, diff, 롤백, 승인 요청서 |
| 개발자 | `.claude/agents/dev-worker.md` | sonnet | 코드 수정 | 범위가 명확한 개발 작업 |

트러블슈팅은 단서 보존을 위해 총괄이 직접 처리한다.

## 2. 가동 방식

| 구분 | 방식 |
|---|---|
| 상시 (예약 작업) | 일일 점검, 주간 성과 리포트 |
| 이벤트 | bot 문의 도착 시 응대 담당 호출 |
| 온디맨드 | 개발, 연구, 문서, 서버 설정은 총괄이 필요할 때 호출 |
| 세션 단위 | 개발 PM은 대형 프로젝트일 때만 별도 세션 |

동시 가동은 3~5개를 넘기지 않는다 (토큰·지연 관리).

## 3. 표준 업무 흐름

**리서치**: 총괄 → researcher 여러 개(병렬) → fact-checker → 총괄 종합 → doc-writer
**서버 변경**: infra-config(변경안) → verifier(재검증) → **센터장 승인** → 총괄이 적용 → daily-check로 확인 → doc-writer(변경 이력)
**bot 문의**: responder(분류, 응답문) → 질문이면 총괄이 자동 전송 / 작업요청이면 센터장 승인 요청 / 에스컬레이션이면 센터장에게만 전달
**개발**: 총괄 → dev-worker(병렬 가능) → verifier → 총괄 보고
**장애**: 총괄 직접 처리 → 해결 후 doc-writer가 런북 작성

## 4. 승인 원칙 요약

- 자동: 읽기 전용, 되돌릴 수 있는 작업, 허용된 발신자에게 가는 bot 응답
- 센터장 승인: 운영 서버 변경, 재시작, 삭제, 배포, 응답 외 외부 발송, 권한·비용
- 읽기 전용 역할은 수정 도구를 주지 않아 구조적으로 보장한다.

## 5. 확장 계획 (성과를 보며 추가)

보안·정책 감사, 성과 분석, 코드리뷰어, 테스트, 신기술 PoC, 네트워크·DB 담당.
추가 기준: 같은 작업을 3번 반복했거나, 검증 단계에서 같은 실수가 반복될 때.

## 6. 운영 규칙

- 역할 정의는 이 저장소에서 버전 관리하고, 에이전트가 틀린 사례는 해당 역할 파일에 규칙으로 반영한다.
- 성과 지표(장애 해결 시간, 응답 정확도, 변경 실패율, 절감 시간)를 주간 리포트로 남긴다.
- 사내 정보를 외부 AI에 보내도 되는지 회사 정책을 먼저 확인한다.
